# Платформа обучения рабочим специальностям — Масштабируемость

**Дата:** 2026-04-11  
**Назначение:** Руководство по переносу архитектуры на новые тематики

---

## Концепция платформы

Приложение "Сварщик с нуля" — первый экземпляр универсальной платформы для обучения рабочим специальностям по российским стандартам. Архитектурные решения, принятые в MVP, намеренно обобщены так, чтобы добавление новой специальности требовало минимум технических изменений.

**Будущие специальности (примеры):**
- Электрик (ПУЭ, ГОСТ Р 50571)
- Строительство каркасных домов (СП 31-105, ГОСТ)
- Сантехник (СП 30, ГОСТ)
- Плиточник / отделочник
- Автомеханик
- Столяр / плотник

---

## Что не меняется между специальностями

### 1. Структура данных контента

Все специальности используют одну и ту же типизацию:

```typescript
Module → Lesson → Step (theory | quiz | interactive)
```

Добавление новой специальности = добавление новой папки в `src/content/`:

```
src/content/
├── welding/         # Сварка (MVP)
├── electrical/      # Электрик (V2)
├── framing/         # Каркасные дома (V2)
└── plumbing/        # Сантехника (V3)
```

Каждая папка содержит `modules/`, `gear/`, `tools/`, `sources.ts` — идентичная структура.

### 2. Интерактивные компоненты

Компоненты написаны без привязки к тематике:

| Компонент | Сварка | Электрика | Каркасные дома |
|---|---|---|---|
| `QuizStep.vue` | Тест по шву | Тест по ПУЭ | Тест по конструкции |
| `DefectChallenge.vue` | Дефекты шва | Неправильная разводка | Ошибки в узлах |
| `ModeCalculator.vue` | Ток/электрод | Сечение кабеля | Шаг стоек |
| `GearGuide` | Сварочный пост | Инструмент электрика | Инструмент плотника |

`DefectChallenge` и `ModeCalculator` принимают конфиг из TypeScript — никакой логики специальности внутри компонентов.

### 3. Система прогресса

`AppProgress` в localStorage работает для любой специальности без изменений. При добавлении мультиспециальности:

```typescript
type AppProgress = {
  specialties: Record<string, SpecialtyProgress>
  //           ^ 'welding' | 'electrical' | ...
}
```

### 4. UX-паттерны

Онбординг (новичок / уже знаком), карта модулей с прогрессивной разблокировкой, пятивкладочная навигация — всё это универсально и переносится без изменений.

### 5. Визуальный язык

Индустриальная тёмная тема, красные акценты, технический шрифт — подходят для любой рабочей специальности. Единый дизайн-язык создаёт узнаваемость платформы.

## Что меняется под каждую специальность

| Элемент | Как адаптируется |
|---|---|
| **Контент уроков** | Новая папка в `src/content/` |
| **Нормативная база** | Свои ГОСТ/СП/ПУЭ в `sources.ts` |
| **Калькулятор** | Новые таблицы в `mode-calculator.ts` (напр. сечение кабеля по нагрузке) |
| **Задачи "найди ошибку"** | Новые SVG/фото + зоны в `defect-challenges.ts` |
| **Раздел снаряжения** | Новый список инструментов с российскими ссылками |
| **Иконка специальности** | Один эмодзи или SVG-иконка |

---

## Архитектура при развитии в мультиспециальность

Когда появится вторая специальность, добавляется экран выбора:

```
/                    → Выбор специальности
/welding/modules     → Карта модулей (сварка)
/electrical/modules  → Карта модулей (электрика)
```

Router становится динамическим — один набор компонентов, контент подставляется по параметру специальности. Pinia store получает параметр `specialtyId`.

## Архитектурные решения v1 (апрель 2026)

### Сервисный слой как контракт

`checklistService.ts` демонстрирует паттерн: все async-методы с одинаковыми сигнатурами.
При добавлении бэка — только меняется тело методов, компоненты не трогаются.
Тот же паттерн нужно применить для: `progressService`, `userService`, `contentService` (для CDN-хостинга контента).

### Контент как данные, не как код

Модули — TypeScript-объекты в `src/content/<specialty>/`. Добавление новой специальности не требует изменения компонентов.
При масштабировании: перенести контент в CMS или JSON API, компоненты останутся теми же.

### Dev-режим как инструмент разработки контента

`useDevMode.ts` — паттерн для будущих авторов контента: разблокировать всё, видеть правильные ответы, переключаться между режимами без сброса прогресса.

### Чеклисты как первый пользовательский UGC

`CustomChecklist` — первый пример пользовательского контента. Архитектура (list → item со структурой) переносима на любую специальность.

### Роутинг готов к мультиспециальности

При добавлении второй специальности: `/welding/*` и `/electrical/*` с общим layout.
Роуты уже организованы по фичам (`/tools/checklists`, `/tools/custom-checklist/:id`).
